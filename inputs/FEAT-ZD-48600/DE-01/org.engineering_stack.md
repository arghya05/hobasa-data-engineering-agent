# org.engineering_stack

Repositories are described by their bindings: ap_aging and ap_forecast and ap_pipeline (Python 3.9, unittest, /usr/bin/python3 ci.py), ap_portal (Node.js 22, node:test, node ci.mjs). Every CI enforces line coverage >= 90% and static checks standing in for SonarQube. Branches main and dev; feature branches per story. Commit messages start with the story ID. No repository uses Databricks or a database; the run's tool views confirm access.
